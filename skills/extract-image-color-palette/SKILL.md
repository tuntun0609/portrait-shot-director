# 提取图片文字色卡

## 核心规则

- 始终运行 `scripts/extract_palette.py` 获取颜色；不要用肉眼或语言模型估算 HEX、RGB 和占比。
- 使用 Pillow 解码、校正 EXIF 方向并执行 `MEDIANCUT` 中位切分量化；使用 NumPy 高效过滤透明像素。
- 默认提取 8 色；用户给出数量时使用用户值，允许 1–16 色。
- 默认忽略完全透明和接近透明的像素，保留半透明像素的原始 RGB。
- 脚本只向标准输出打印文字，不生成 PNG、JSON、CSS 或其他结果文件。
- 直接把脚本结果整理到最终回复中，不额外制作可视化色卡。

## 工作流程

### 1. 确认输入

1. 解析用户指定的本地图片路径；没有可访问的图片时，请用户重新附加或提供路径。
2. 有多张图片时逐张运行，并在最终回复中按图片分组。
3. 用户没有指定颜色数时使用 8；只有在用户要“单一主色”时使用 1。

### 2. 运行脚本

将命令的工作目录设置为本技能的目录，再使用当前环境中已安装 Pillow 和 NumPy 的 Python 解释器执行。不要假设技能安装在某个固定用户目录、项目目录或虚拟环境中。

```bash
python3 scripts/extract_palette.py \
  /absolute/path/to/input.png \
  --colors 8
```

`python3` 只是命令示例；如果当前项目已声明 Python 环境或虚拟环境，优先使用该环境的解释器。运行前可用下面的命令确认依赖可用：

```bash
python3 -c "import PIL, numpy"
```

不要仅为调用脚本而写死解释器绝对路径，也不要假设某个 `.venv` 必然存在。

可选参数：

- `--colors <1...16>`：色卡颜色数量。
- `--max-size <128...2048>`：分析缩略图的最大边长，默认 640；细碎、多彩图片可提高到 1024。
- `--alpha-threshold <0...255>`：忽略 alpha 小于等于该值的像素，默认 12。
- `--help`：查看完整命令帮助。

脚本输出图片尺寸、采样尺寸、有效像素数，以及按占比排序的文字色卡：

```text
1. #C85A3A | RGB(200, 90, 58) | 31.42%
2. #F2D6B3 | RGB(242, 214, 179) | 24.17%
```

### 3. 验证并交付

1. 确认命令退出状态为 0，输出的颜色数量与请求一致；图片实际颜色不足时可以少于请求数。
2. 核对每项都包含排名、HEX、RGB 和占比；占比总和应接近 100%。
3. 在最终回复中直接列出脚本输出的文字色卡，可省略算法和采样元数据，除非用户询问。
4. 不创建或链接色卡文件，不把输出转换成图片、表格或代码文件。

## 失败处理

- 依赖导入失败：先检查当前项目声明的 Python 环境或已有虚拟环境。仍无可用环境时，说明缺少 Pillow 和 NumPy；只有得到用户许可后才安装依赖。
- 图片无法解码：确认文件真实格式与扩展名一致；必要时用系统工具临时转换为 PNG 后重试，不修改原文件。
- 图片没有可分析像素：把 `--alpha-threshold` 调低后重试；不要擅自给透明区域添加背景色。
- 颜色过于相近：把颜色数从 8 降为 5 或 6 后重跑。
- 小面积强调色未被提取：把颜色数提高到 10–12，并把 `--max-size` 提高到 1024 后重跑。
